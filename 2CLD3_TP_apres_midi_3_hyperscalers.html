1. Objectif pédagogique

La présentation des trois hyperscalers ne doit pas se limiter à « AWS, Azure, GCP font du Cloud ». Il faut aider les étudiants à comprendre que chaque fournisseur a une histoire, une culture technique, un écosystème, des forces et des contraintes.

Réponse courte à transmettre : AWS est souvent perçu comme le pionnier très riche en services et très mature ; Azure est très fort dans les entreprises déjà Microsoft et l’hybride ; Google Cloud est très différenciant sur la donnée, Kubernetes, l’IA et l’ingénierie issue de Google.
Piste de réflexion : dans un vrai projet, le meilleur Cloud n’est pas le plus « populaire » : c’est celui qui correspond au contexte métier, aux compétences internes, aux contraintes de sécurité, aux coûts, aux services nécessaires et à la stratégie de l’entreprise.

2. Le marché : pourquoi parle-t-on surtout d’AWS, Azure et Google Cloud ?

Top 3

AWS, Azure et Google Cloud dominent le marché mondial des services d’infrastructure Cloud.

≈ 2/3

Plusieurs analyses de marché 2025 situent leur poids cumulé autour de deux tiers du marché mondial.

IA

La croissance récente est fortement tirée par l’IA, la donnée, les GPU, les plateformes d’agents et les services managés.

Point important : les parts de marché changent selon les cabinets, les périmètres et les trimestres. Pour un cours, il vaut mieux retenir la tendance : AWS reste très fort, Azure progresse fortement en entreprise, Google Cloud croît grâce à la donnée et l’IA.

AWS – Amazon Web Services

Positionnement : pionnier du Cloud public moderne, très large catalogue de services, forte maturité IaaS/PaaS, énorme écosystème.

Forces : richesse fonctionnelle, maturité, documentation, choix d’instances, services managés, réseau mondial, culture DevOps.

Limites : complexité du catalogue, coûts parfois difficiles à anticiper, gouvernance indispensable, risque de dépendance fournisseur.

Cas typiques : startup qui veut scaler vite, plateforme web mondiale, architecture serverless, data lake, IA, e-commerce, SaaS.

EC2S3LambdaRDSEKSIAM

Microsoft Azure

Positionnement : Cloud très présent dans les grandes entreprises, naturellement lié à Microsoft 365, Windows Server, Active Directory, SQL Server, .NET et GitHub.

Forces : intégration entreprise, identité Entra ID, hybride/multicloud avec Azure Arc, sécurité, conformité, AKS, DevOps, liens Microsoft/OpenAI.

Limites : portail parfois dense, nomenclature changeante, gouvernance à cadrer, coûts pouvant dériver sans FinOps.

Cas typiques : SI d’entreprise Microsoft, migration d’applications .NET/SQL Server, environnement réglementé, stratégie hybride, DevOps Azure.

VMBlob StorageFunctionsAzure SQLAKSEntra ID

Google Cloud

Positionnement : Cloud très orienté data, analytics, Kubernetes, IA/ML et infrastructure issue de l’expérience Google.

Forces : BigQuery, GKE, réseau mondial Google, Cloud Run, Vertex AI, approche développeur, data engineering.

Limites : part de marché plus faible que AWS/Azure, moins dominant dans certains grands comptes historiques, écosystème parfois moins connu des équipes classiques SI.

Cas typiques : analytics massif, IA/ML, conteneurs, applications cloud-native, startup orientée produit/data, plateforme événementielle.

5. Corrigés et pistes de réflexion

Corrigé scénario 1

Réponse attendue : Azure est le choix naturel en première intention. La raison n’est pas que les autres Clouds seraient incapables, mais que l’écosystème existant est déjà Microsoft : identité, postes, collaboration, Windows Server, SQL Server, outils d’administration et compétences internes.

Piste pro : en migration réelle, on regarde aussi la dette applicative, les licences, l’hybridation, le réseau, les sauvegardes, la sécurité et l’industrialisation via IaC.

Corrigé scénario 2

Réponse attendue : AWS est souvent très pertinent pour une startup SaaS mondiale grâce à son catalogue, sa maturité, son écosystème et sa scalabilité. Mais Azure ou Google Cloud peuvent aussi être pertinents selon les compétences, les services nécessaires et les partenariats.

Risques : explosion des coûts, architecture trop complexe, dépendance fournisseur, sécurité mal cadrée, absence de supervision. Message DevOps : automatiser, mesurer, alerter, taguer les ressources, documenter.

Corrigé scénario 3

Réponse attendue : Google Cloud est un candidat très naturel pour data/analytics/IA, notamment grâce à BigQuery, Vertex AI, GKE et l’héritage technique Google. AWS et Azure ont aussi des offres très solides, mais Google Cloud est souvent différenciant sur l’expérience data.

Piste pro : le choix dépend aussi de l’endroit où sont déjà les données, du coût de transfert, de la gouvernance, de la conformité et des compétences data internes.

Corrigé scénario 4

Réponse attendue : non, ce n’est pas uniquement une question de fournisseur. Les trois grands acteurs proposent régions, chiffrement, IAM, logs, certifications et services de sécurité. Le vrai sujet est l’architecture de gouvernance : choix de région, politique d’accès, chiffrement, réseau, sauvegarde, journalisation, conformité et contrôle des coûts.

Piste pro : c’est là qu’interviennent les pratiques DevOps/IaC : policy as code, modules Terraform, landing zones, séparation des environnements, RBAC, monitoring, budgets et alerting.

6. Conclusion à donner aux étudiants

Formulation simple : “AWS, Azure et Google Cloud permettent tous de déployer des applications modernes. La vraie compétence n’est pas de réciter leurs noms de services, mais de comprendre les critères de choix : contexte métier, compétences, coûts, sécurité, données, réseau, conformité, automatisation et exploitation.”

Lien avec l’expérience DevOps : dans la réalité, un Cloud mal gouverné devient vite coûteux et fragile. Terraform, CI/CD, supervision, sécurité et FinOps ne sont pas des bonus : ce sont les outils qui permettent d’utiliser le Cloud professionnellement.
